## 逐項結果

### 1. 在 Claude 兩個 Chat 對話之間切換，各自顯示正確的便利貼；Cowork、Code 各測一次

**結果：待手動驗證**

重現：在兩個 Chat 對話各貼一張不同內容的便利貼，來回切換。Cowork、Code 各貼一張，切到別的 session 再回來。（清單 A1–A3）

證據：

- 辨識：`ClaudeIdentificationTests` 用報告 0002 在真實 Claude 上錄下的 11 份快照測試，Chat、Cowork、Code 都能取得對話 ID 與標題，也確認了網址格式與切換延遲（通知與網址在 5ms 內同時改變）。
- 引擎：`ConversationScopeTests`「在對話上按 ⌘⌥N，便利貼綁在該對話」「切到別的對話時立刻隱藏，回來時在原位置出現」「對話範圍與視窗範圍的便利貼同時顯示」「對話改名後標籤顯示新標題」。
- 還沒有在真實 Claude 上把便利貼貼上、切換過。

### 2. 新對話頁拒絕貼並提供「改貼在這個視窗」；點側欄舊對話不誤判

**結果：待手動驗證**

重現：在 Chat 的新對話頁、Cowork 的新任務頁、Code 首頁各按一次 ⌘⌥N，看提示並按「改貼在這個視窗」。再從新對話頁點側欄裡的舊對話。（清單 A4、A5）

證據：

- 辨識：`ClaudeIdentificationTests`「新對話頁（Chat、Cowork、Code 首頁、被導回的已刪除對話）是草稿」，素材是真實快照。
- 引擎：`ConversationScopeTests`「新對話頁不能貼：告知原因，也不建立便利貼」「新對話頁選「改貼在這個視窗」，綁在 Claude 視窗」。
- 不確定：報告 0002 的切換延遲是用 `claude://` 量的，用滑鼠點側欄的延遲沒有量過。App 另有每 0.5 秒的輪詢補漏。

### 3. 快速連續切換對話或 App 時，舊便利貼不閃到新內容上

**結果：部分通過**

重現：在幾個 Claude 對話之間快速連點側欄，再用 ⌘Tab 在 Claude 與其他 App 之間快速切換。看舊便利貼有沒有短暫出現在新內容上。（清單 A6）

證據：

- 引擎：`ConversationScopeTests`「在對話之間快速切換，不會在新對話上出現舊對話的便利貼」；`WindowScopeTests`「焦點正在變動、還無法確定時，先隱藏綁定的便利貼」。
- 實機：ticket 05 在兩個 Finder 視窗之間切換，各自顯示自己的便利貼，沒有閃爍。切到不同 App 時，App 先送「無法辨識」再讀 AX；新出現的便利貼等焦點穩定 80ms 後才淡入。
- Claude 對話之間的快速切換還沒在實機上試過。

### 4. 移動、縮放、最小化 Claude 視窗，進出全螢幕，在兩個螢幕之間移動

**結果：部分通過**

重現：在 Claude 視窗貼一張，依序移動、縮放、最小化再還原、進出全螢幕、拖到另一個螢幕。把外接螢幕改排在主螢幕上方、再改排在左側，各做一次建立與移動。（清單 B1–B3）

證據：

- 引擎：`WindowScopeTests`「跟著視窗走」整組（移動、換螢幕、放大縮小、超出視窗、螢幕邊緣、全螢幕）與「視窗最小化時隱藏，還原時重新出現」；`ScreenCoordinatesTests` 涵蓋位在上方（y 為負）與左側（x 為負）的副螢幕；`NoteEngineTests`「多螢幕」。
- 實機：ticket 05 用 Finder 視窗，在內建螢幕加右側外接 2560×1440 上驗證過：移動、縮放、移到外接螢幕、最小化與還原、在外接螢幕上全螢幕都跟著走。報告 0003 驗證過便利貼能出現在別的 App 的全螢幕空間上。
- 待手動驗證：用 Claude 視窗做一次（Claude 是 Electron App，AX 通知可能和 Finder 不同）；外接螢幕排在上方或左側時的建立位置與跟隨（ticket 13）。

### 5. 重開 Claude 與 Hintlet 後，便利貼都在且正確對應回對話

**結果：待手動驗證**

重現：在 Chat、Cowork、Code 各貼一張，結束 Claude 再打開；再結束 Hintlet 再打開。看便利貼是否回到原本的對話，位置與收合狀態不變。（清單 A7）

證據：

- 引擎：`ConversationScopeTests`「Claude 重開後（新的視窗身分）對話的便利貼直接回來」；`PersistenceTests`「儲存與讀回」與「格式版本」兩組（以新引擎讀回同一資料夾、版本遷移）。
- 對話以 Claude 的對話 ID 綁定，不靠視窗身分，所以 Claude 重開後不必進待找回。這條規則已有測試，但還沒在實機上重開過。

### 6. 便利貼取得焦點時，不因前景變成自己而隱藏造成循環

**結果：通過（一種情況待手動驗證）**

重現：在任何 App 按 ⌘⌥N 打字，再按 Esc；點一下既有便利貼打字；打字後不按 Esc，直接點底下 App 的視窗。（清單 B4）

證據：

- 引擎：`WindowScopeTests`「前景變成 Hintlet 自己時沿用前一個工作內容，便利貼不被隱藏」「前景是 Hintlet 自己時新增的便利貼，仍綁在前一個視窗」。
- 實機：報告 0003 在全螢幕的 TextEdit 上驗證，⌘⌥N 後打字，按 Esc 後前景交還 TextEdit；點既有便利貼打字不改變前景。ticket 05 在 Finder 上 ⌘⌥N 後按 Esc 交還 Finder，沒有閃爍。
- 待手動驗證：不按 Esc、直接點別的視窗結束編輯（報告 0003 沒測）。

### 7. 一般視窗綁定（例如 Finder）與重啟後的「可能是這裡？」提示

**結果：部分通過**

重現：在 Finder 資料夾貼一張，另開視窗到同一資料夾、重開 Finder。在讀不到路徑的視窗（例如系統設定）貼一張，結束那個 App 再打開，等標題相同的視窗出現，按「可能是這裡？」。（清單 F1–F3）

證據：

- 實機：ticket 05 在兩個 Finder 視窗上驗證各自顯示自己的便利貼。之後依使用者的實機回饋，Finder 改成綁在資料夾上（規格故事 32a）。
- 引擎：`DocumentScopeTests`（資料夾綁定、另一個視窗打開同一資料夾、重啟後直接出現、資料夾不見時進待找回）；`PersistenceTests`「重新啟動後的視窗便利貼」整組（不以標題自動貼上、同 App 同標題才提示、確認後回到相對位置、按 × 後不再提示），以及「只有 Hintlet 重新啟動時」整組。
- 待手動驗證：重啟後「可能是這裡？」的提示與確認，ticket 06 沒有留下實機紀錄；第一次詢問「控制 Finder」權限的流程。

### 8. 刪除後復原；Code session 被刪時便利貼進垃圾桶

**結果：待手動驗證**

重現：刪掉一張有字的便利貼，按「復原」；再刪一次，6 秒內按 ⌘Z。在 Code session 上貼一張，然後在 Claude 裡刪掉那個 session，等 30 秒，打開列表看垃圾桶。（清單 E1–E4）

證據：

- 引擎：`NoteEngineTests`「刪除的便利貼不再顯示，但進垃圾桶保留，可以復原到原處」；`TrashTests`（30 天到期、永久刪除、清空，以及「Code session 消失，它的便利貼移到垃圾桶」「Chat 對話的便利貼不因任何偵測而移走」）；`SessionDeletionTests`（Code 的 `deleted_<uuid>` 記號一次就確定；Cowork 要連續兩次都找不到；短暫消失不算）。
- 「已刪除・復原」提示與提示期間的 ⌘Z 已實作（ticket 10），沒有在實機上試過。

## 支援矩陣

狀態的意思：

- **已驗證**：辨識方法在真實 App 上確認過，也有自動測試，屬於正式支援。完整的端到端操作仍要照「實機驗收」欄完成。
- **實驗**：已經實作，但辨識鏈裡還有一步沒在真實 App 上確認過，可能完全不能用。不能用時一律安全降級到較粗的範圍，不會貼錯。
- **未支援**：沒有這個範圍，只能用括號裡較粗的範圍。

## 已知限制

### 辨識與綁定

1. **Codex 只有視窗範圍。** Codex 的對話路由不在 AXURL 中，只能靠標題，不符合可靠識別的要求（ADR-0001）。
2. **私密瀏覽與無痕視窗只在英文介面實測過。** Safari 以網址列的說明（「in a private window」，也認「私密」「隱私」）、Chrome 以視窗標題結尾「(Incognito)」或「Incognito／無痕模式」按鈕辨識；其他語言的介面可能認不出，那時私密視窗的網頁便利貼會照一般網頁綁定，網址會寫進 `notes.json`。
3. **Chrome 讀不到網址（已實測）。** App 不會替 Chrome 開啟完整輔助使用樹，所以 Chrome 只有視窗範圍。需要的話，要比照 Claude 先徵得同意再開。
4. **網頁以網址辨識。** `?` 後的參數保留（YouTube 的 `?v=` 是不同影片），所以帶追蹤參數的同一頁會被當成不同網頁。單頁應用在同一分頁內換網址，靠每 0.5 秒的輪詢發現。
5. **Claude 的辨識依賴非公開的介面**（網頁區域的 AXURL、Chat 的訊息 class、Cowork／Code 的 session 檔）。Claude 改版後讀不到時會降級，不會貼錯。
6. **Claude 完整輔助使用樹的資源成本只量過「開啟後」**：renderer 約 1.1GB RSS。沒有和關閉時對照過。
7. **Claude 有多個網頁區域時降級。** 多個 Claude 視窗的情況沒有錄過快照。
8. **Chat 對話被刪除時，便利貼不會自動移走**（Chat 沒有本機檔可以偵測）。Cowork 刪除要 30–60 秒才確定，而且沒驗證過刪除時 session 檔真的會消失。
9. **列表的「前往」若落在新對話草稿**（對話已被刪除），不會把便利貼標成待找回。
10. **一般 App 重啟後，視窗便利貼一律進「待找回」。** 只有同一個 App、標題完全相同的視窗會出現「可能是這裡？」；沒有標題的視窗、讀不到 bundle ID 的 App 不會提示，只能從列表找回。
11. **終端機裡的 Claude Code**：Terminal 回報的視窗名稱必須和 AX 標題逐字相同才問得到 tty，否則永遠降級；終端機在前景時每秒檢查一次；啟動後沒送出訊息就離開的 session 無法 resume，便利貼會留在待找回；session 檔格式不是公開介面。
12. **Code 的 `lastFocusedAt` 沒有使用。** 它在切換後約 3 秒才寫入，只能事後校正。

### 顯示與操作

13. **⌘⌥N 會讓 Hintlet 短暫成為前景 App**，這樣鍵盤輸入才會送進便利貼（ticket 01 的偏離，使用者已同意）。引擎會沿用前一個工作內容，不會因此隱藏便利貼。
14. **視窗移動或縮放時，便利貼先淡出讓開，停下 0.15 秒後回到相對位置。** 另一個程式的視窗無法和視窗伺服器的動畫逐幀同步，這是刻意的取捨。
15. **綁定的便利貼只屬於它所在的桌面**，切換桌面時跟著滑走；浮動便利貼出現在所有桌面。
16. **「已刪除・復原」顯示的 6 秒內，⌘Z 會被 Hintlet 接走**，就算前景是別的 App。淡出後還給原本的 App。
17. **快捷鍵和其他 App 衝突時，多半偵測不到。** 只能偵測到和 Hintlet 自己、和系統「鍵盤快速鍵」的衝突，以及系統拒絕註冊的情況。
18. **在全螢幕 App 結束編輯後再按一次 Esc**，會送到那個 App（TextEdit 會因此退出全螢幕）。這是正常行為。

### 交付與資料

19. **沒有「登入時自動開啟」。** 重開機後要自己打開 Hintlet，或在「系統設定 › 一般 › 登入項目」加入。
20. **只在本機使用。** 沒有公證（notarize），也沒有 Developer ID 簽章，不能直接傳給別人用。沒有 iCloud 同步。
21. **沒有 App Sandbox**，因為輔助使用與跨 App 讀取在 sandbox 中受限。
22. **ad-hoc 簽章時，每次重建都要重新授權輔助使用。** 用固定的開發團隊簽章就不會（見 README）。
23. **資料是單一 JSON 檔**，含最近 5 份備份。讀不懂的檔案會移到 `notes.unreadable-N.json`，不會被覆蓋。
24. **AI 便利貼的摘要能力看後端。** 裝置端模型的上下文約 4096 個 token，只送最新的一問一答、放得下的較早訊息和最初的要求（不送上一次的摘要，小模型會照抄）；摘要偶爾不夠具體。Claude 帳號、Codex 帳號與兩種 API key 會把 AI 便利貼所在對話的內容上傳，各自要先同意。Chat 只根據頁面已載入的訊息。啟動時裝置端模型還沒準備好，這次執行就不提供它，重開 Hintlet 後才會出現。
