# 手動驗證清單：Hintlet v1（手寫便利貼 MVP）

把 ticket 07–12、17、18 留下的手動檢查，和 ticket 13 的外接螢幕排列，集中在這一份。照順序做，每做完一項打勾；結果不對時，在項目下面寫一行看到了什麼，再回報。

每一項後面的「→」是它對應的驗收項目（[驗證報告](0001-mvp-verification.md)）或 ticket。

## 開始前

- [ ] 先備份真實資料：`cp ~/Library/Application\ Support/com.jyp.hintlet/notes.json ~/Desktop/notes-before-checks.json`。H2 的匯入請用一份測試檔，不要用這份。
- [ ] 照 [README](../../README.md) 建置並打開 Hintlet。選單列「設定… › 權限」顯示輔助使用「已開啟」。
- [ ] 一台 Mac 接一個外接螢幕（B2、B3 要用）。

## A. Claude 對話（ticket 07）

- [ ] **A1** 在兩個 Chat 對話各貼一張不同內容的便利貼，來回切換：每個對話只出現自己的那張，標籤是「Claude 對話：<標題>」。→ 驗收 1
- [ ] **A2** Cowork 的一個 session、Code 的一個 session 各貼一張，切到別的 session 再回來。→ 驗收 1
- [ ] **A3** 第一次在 Claude 按 ⌘⌥N 時，詢問是否讓 Claude 開啟完整輔助使用資訊。先選「只用視窗範圍」：便利貼綁在視窗；之後從選單列「認得 Claude 的對話」打開，再按一次 ⌘⌥N 就綁在對話。→ ticket 07
- [ ] **A4** 在新對話頁（Chat 的 New session、Cowork 的 New task、Code 首頁）按 ⌘⌥N：出現「新對話還沒建立，送出第一則訊息後再貼」與「改貼在這個視窗」；按後者，便利貼綁在 Claude 視窗。→ 驗收 2
- [ ] **A5** 從新對話頁點側欄的舊對話：舊對話的便利貼出現，沒有被當成草稿或降級。用 `swift Tools/claude-ax-probe.swift watch 20` 量一次點側欄時網址變化與通知的時間差，記在下面。→ 驗收 2、報告 0002
- [ ] **A6** 在幾個對話之間快速連點側欄，再用 ⌘Tab 在 Claude 與其他 App 間快速切換：舊對話的便利貼從來沒有閃現在新對話或別的 App 上（寧可晚一點出現）。→ 驗收 3
- [ ] **A7** 結束 Claude、再打開；再結束 Hintlet、再打開：A1、A2 的便利貼都回到原本的對話，位置與收合狀態不變。→ 驗收 5
- [ ] **A8** 在既有對話上打開 Claude 設定：對話的便利貼先收起，視窗範圍的照常；關掉設定後回來。→ ticket 07、報告 0002
- [ ] **A9** 在專案頁按 ⌘⌥N：標籤寫「視窗（認不出對話）：…」，下方有提示。→ ticket 07
- [ ] **A10** 開兩個 Claude 視窗，各顯示不同對話：各自只出現自己的便利貼，或明確降級，不會貼錯。→ ticket 07

- [x] **I1** Safari 一般網頁：網頁區域只有一個、`AXURL` 是完整網址、標題是網頁標題。（2026-10-19：一個網頁區域，AXURL 是完整網址）
- [ ] **I2** Safari 切分頁、在 YouTube 同一分頁點下一部影片：記下通知與網址變化的延遲。
- [x] **I3** Chrome（不開完整輔助使用樹）讀不讀得到網頁區域與 `AXURL`。讀不到時記下來，Chrome 就維持視窗範圍。
- [ ] **I4** 在 Safari、Chrome 各貼一張網頁便利貼：換分頁收起、回來出現；另一個視窗開同一網址時出現在那裡；兩個瀏覽器與 Hintlet 重開後直接回來。小島第二排有「網頁」。

## K. Code 與 Cowork 的 AI 便利貼（ticket 14）

需要 macOS 26 以上、已開啟 Apple Intelligence 的 Mac。不符合時 K1 改成確認完全看不到 AI 的選項。

- [ ] **K1** 在 Code session 按 ⌘⌥N：空白便利貼下方半透明顯示「✨ 讓 AI 記錄脈絡？」。打一個字就消失。在視窗或浮動便利貼上不出現（Chat 見 L）。
- [ ] **K2** 按下選項：便利貼換成 AI 便利貼的顏色、不能打字，先顯示「正在讀取對話…」，幾秒內換成粗體的目標、一行重點（結論本身），需要你時再一行下一步（等你／卡住／進行中），和「更新於 …」，內容和這個 session 對得上。
- [ ] **K3** 同一個 session 再按 ⌘⌥N：新便利貼不再出現選項。按住小島：沒有「轉成 AI 便利貼」。
- [ ] **K4** 在 session 裡多聊一句，切到別的 session 或別的 App，再回來：三行與更新時間已更新。沒有新訊息時切走，更新時間不變。
- [ ] **K5** 按住 AI 便利貼的小島：一列圖示，依序是「更新」、「轉成一般便利貼」與垃圾桶（沒有顏色與範圍選項）。按「更新」看到「正在更新…」後更新時間改變；按「轉成一般便利貼」後變回可編輯的便利貼，內容就是轉換前 AI 便利貼顯示的那句摘要。
- [ ] **K5b** Claude 在 AI 便利貼的對話回完一則訊息，十幾秒內 AI 便利貼更新；Claude 還在回時不更新。字多時可以捲動。
- [ ] **K6** 剛貼下的空白便利貼按住小島，第三列「✨ 轉成 AI 便利貼」可用，效果同 K2。
- [ ] **K7** Cowork session 重複 K1–K2。
- [ ] **K8** 重開 Hintlet：AI 便利貼和摘要都在，仍是唯讀淡藍。
- [ ] **K9** 確認 Claude 的 session 檔與 `~/.claude/projects` 裡的紀錄沒有被改動（修改時間不變），也沒有任何網路連線（例如用 Little Snitch 或「活動監視器 › 網路」看 Hintlet）。

## L. Chat 的 AI 便利貼（ticket 15）

條件同 K（或在設定中改用 Claude API）。用一個測試用的 Chat 對話，不要用重要的對話。

- [x] **L1** 在測試 Chat 對話按 ⌘⌥N：出現「✨ 讓 AI 記錄脈絡？」；按下後幾秒內換成三行，下方寫「僅根據已載入的 N 則訊息」。N 和畫面上已載入的訊息數對得上（短對話就是全部訊息數）。（2026-10-19 通過：6 則，與頁面上 3 問 3 答相符）
- [ ] **L2** 在一個長對話（例如請 Claude 列 200 行數字三次以上）停在底部時做 L1：N 小於全部訊息數，三行只講到已載入的部分，沒有編出看不到的前文。Hintlet 沒有替你捲動對話。
- [x] **L3** 只有「嗨」「你好」兩則的新 Chat：AI 便利貼顯示「對話內容還不夠，之後再記錄脈絡。」，不是編出來的三行。（2026-10-19：起初寫出照抄指示的三行，改成看使用者說了多少後通過）
- [x] **L4** 在有 AI 便利貼的 Chat 多聊一句，等約 10 秒後切到另一個 Chat 對話，再切回來：三行與更新時間已更新。切走前不到 8 秒就切，可能還是上一次的內容（只讀得到切走前最後一次讀到的頁面）。（2026-10-19：換話題後摘要停在舊話題；改為以最新一問一答為準、不放上一次的摘要（模型會照抄）後通過）
- [ ] **L5** 在沒有 AI 便利貼的 Chat 對話停留、切換：Hintlet 不讀內容（用 `log stream --predicate 'process == "Hintlet"'` 沒有異常；可用「活動監視器」看 Hintlet 的 CPU 在這些對話上維持平常水準）。刪除 AI 便利貼之後也一樣。
- [x] **L6** 第一次開啟 Claude 輔助使用資訊時的說明與設定裡「Claude 對話」開關下的說明，寫的是「只有開了 AI 便利貼的 Chat 對話才讀取已載入的訊息」。（2026-10-19：兩處文字都已確認，`App/ClaudePages.swift` 的說明與 `App/SettingsPanes.swift` 的開關說明）

## M. 由誰寫 AI 便利貼與 AI 便利貼顏色（ticket 16）

設定 › AI 有五個選項：裝置端模型、Claude 帳號（透過 Claude Code）、Codex 帳號（透過 Codex）、Claude API key、OpenAI API key。帳號的兩個要先在終端機登入（Claude Code 在 `claude` 裡輸入 `/login`；Codex 執行 `codex login`），用量算在你的方案裡；API key 的兩個要一把自己的 key（會產生少量費用）。不想上傳時只做 M1、M2、M2b、M6。

- [ ] **M1** 設定 › AI：沒有 Apple Intelligence 的 Mac 上「裝置端模型」顯示「這台 Mac 無法使用」且不能選。
- [ ] **M2** 依序選四個會上傳的選項：每個都先跳出各自的「改用 Claude 帳號？」「改用 Codex 帳號？」「改用 Claude API？」「改用 OpenAI API？」，寫明內容交給誰、上傳到哪裡（Anthropic 或 OpenAI）、算帳號用量還是由 API key 付費；按「取消」後仍是原本的選項。
- [ ] **M2b** 「Claude Code 與 Codex」區：Claude Code 顯示 `/opt/homebrew/bin/claude`（或你裝的位置），Codex 顯示 ChatGPT.app 裡附的那一份（`…/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`）。按 Codex 的「選擇…」選一個不能執行的檔案（例如一張圖）：顯示「這個檔案不能執行…」，路徑不變。選一個可以執行的 codex 後出現「自動尋找」，按下回到自動找到的那一份。找不到的 CLI 寫「找不到」，對應的選項寫「（找不到 …）」且不能選。（2026-10-19：程式找到 `/opt/homebrew/bin/claude` 與 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`；設定畫面的顯示未看）
- [ ] **M3** 選「Claude API key」並按「改用並上傳」：下方出現「Claude API key」欄位。貼上 key 按「儲存」：顯示「已儲存在鑰匙圈」。打開「鑰匙圈存取」能找到「Hintlet Claude API key」。重開設定仍顯示已儲存。
