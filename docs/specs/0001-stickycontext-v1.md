# Hintlet v1

用語以 [CONTEXT.md](../../CONTEXT.md) 為準；相關決策見 [ADR-0001](../adr/0001-identify-claude-conversations-via-ax-url.md)、[ADR-0002](../adr/0002-write-from-scratch-instead-of-forking-tack.md)。

## Problem Statement

我同時開著好幾個 Claude 對話（Chat、Cowork、Code）和其他 App 視窗，每次切走再切回來，都要花時間回想「這個對話剛剛做到哪、下一步要幹嘛」。現有的便利貼工具不是固定在螢幕上（切到哪都看得到，跟內容無關），就是只能綁到「視窗」——但 Claude 只有一個視窗，裡面切換的才是我真正的工作內容。用視窗標題猜也不行：Claude 的視窗標題永遠是「Claude」。我需要一張會「跟著工作內容走」的便利貼：回到哪個對話，就看到那個對話的筆記；而且當 App 認不出內容時，它要老實說，而不是貼錯地方讓我誤會。

## Solution

一個只住在選單列的 macOS App。按 ⌘⌥N，就在游標位置貼一張便利貼，自動綁定到目前能確實辨識的最細工作內容——Claude 的某個對話，或某個 App 視窗——並在便利貼頂端標明綁到哪裡、哪種範圍。切到別的內容時便利貼隱藏，回來時在原位置、原收合狀態重新出現，且跟著視窗移動。認不出細部內容時明確降級到視窗；綁定失效時便利貼進「待找回」，不會消失也不會亂貼。集中列表可搜尋所有便利貼、找回待找回者、從垃圾桶復原。第二階段加入 AI 便利貼：替某個對話自動維持「目標／重點／下一步」摘要，切回對話時一眼抓到在做什麼、得出了什麼、要看什麼，與手寫便利貼完全分開。

## User Stories

### 建立與編輯

1. 身為使用者，我想按 ⌘⌥N 就在目前工作內容上貼一張便利貼，讓我不用離開手上的工作去開別的 App。
2. 身為使用者，我想讓新便利貼出現在滑鼠游標的位置，讓我一個動作就決定它貼在哪。
3. 身為使用者，我想在游標不在目前視窗內時，新便利貼出現在視窗右上角並與既有便利貼錯開，讓它不會跑到別的螢幕或疊在一起。
4. 身為使用者，我想在同一個工作內容上貼多張便利貼，讓我可以把不同主題分開寫。
5. 身為使用者，我想新便利貼建立後立刻可以打字，讓我不必再點一下。
6. 身為使用者，我想在便利貼裡寫純文字與可點擊勾選的清單項目，讓我能記待辦並逐項打勾。
7. 身為使用者，我想內容自動儲存，讓我不需要按儲存也不怕當機遺失。
7a. 身為使用者，我想結束編輯時還是空白的便利貼自動丟掉，讓誤按或沒寫的便利貼不會累積成空白卡片與「可能是這裡？」提示。
8. 身為使用者，我想拖曳便利貼改變位置，讓它不擋住我要看的內容。
9. 身為使用者，我想拖曳邊角調整便利貼大小，讓長短內容都放得下。
10. 身為使用者，我想把便利貼收合成一個小標籤（顯示第一行開頭），讓它不佔空間但我仍知道它在那。
11. 身為使用者，我想點小標籤就展開便利貼，讓我隨時看完整內容。
12. 身為使用者，我想每張手寫便利貼可從 5 種顏色中選擇（預設黃色），讓我用顏色分類。
13. 身為使用者，我想在便利貼上編輯時，便利貼不會因為「前景 App 變成 Hintlet」而消失或閃爍，讓我能安心打字。

### 刪除與復原

14. 身為使用者，我想刪除便利貼後看到「已刪除・復原」提示，讓誤刪能一鍵救回。
15. 身為使用者，我想用 ⌘Z 復原剛才的刪除或編輯，讓操作符合 macOS 習慣。
16. 身為使用者，我想被刪除的便利貼進垃圾桶保留 30 天，讓我事後還能從列表找回。
17. 身為使用者，我想在垃圾桶裡永久刪除或清空，讓我能控制資料。

### 綁定與範圍

18. 身為使用者，我想新便利貼自動綁定到目前能確實辨識的最細範圍，讓我不必每次選擇。
19. 身為使用者，我想每張便利貼頂端顯示範圍標籤（例如「💬 Claude 對話：重構登入流程」或「🪟 視窗：Finder — Downloads」），讓我知道它綁在哪。
20. 身為使用者，我想點範圍標籤開選單，把範圍改成「對話／整個視窗／浮動」，讓我修正預設選擇。
21. 身為使用者，我想從範圍選單「重新綁定到目前內容」，讓我把便利貼搬到另一個對話或視窗。
22. 身為使用者，我想在 Claude Chat 的某個對話貼的便利貼，只在回到該對話時出現，讓不同對話的筆記不混在一起。
23. 身為使用者，我想 Claude Cowork 與 Code 的每個 session 也各自綁定，讓三種分頁都能用。
24. 身為使用者，我想綁在「整個 Claude 視窗」的便利貼在該視窗所有對話都出現，讓我寫跨對話的備忘。
25. 身為使用者，我想同時看到對話範圍與視窗範圍的便利貼，各自標示範圍，讓我不會漏看。
26. 身為使用者，我想在新對話頁（尚未送出、沒有對話 ID）按 ⌘⌥N 時看到提示「新對話還沒建立，送出第一則訊息後再貼」與「改貼在這個視窗」按鈕，讓我知道為什麼不能貼並有替代做法。
27. 身為使用者，我想在 Claude 的專案頁等非對話頁貼便利貼時，明確降級到視窗範圍並在標籤上寫明，讓我不被假的精準度誤導；打開 Claude 設定時，底下對話的便利貼先隱藏，關掉設定再出現。
28. 身為使用者，我想對話改名後便利貼仍綁在原對話，且標籤顯示新名稱，讓改名不影響筆記。
29. 身為使用者，我想對話封存後便利貼仍綁定，列表標示「已封存」，讓我知道狀態。
30. 身為使用者，我想 Claude Code 或 Cowork session 被刪除時，它的便利貼自動移到垃圾桶，讓列表不堆積無主筆記。
31. 身為使用者，我想 Claude Chat 對話的便利貼不會因為無法偵測刪除而被自動處理，讓我的筆記不被誤刪。
32. 身為使用者，我想在任何其他 App（例如 Finder、VS Code）上以視窗範圍貼便利貼，讓工具不只限於 Claude。
32a. 身為使用者，我想在顯示資料夾或文件的視窗（Finder 資料夾、Pages、預覽程式等）貼的便利貼綁在那個資料夾／檔案上：任何視窗打開它就出現，同一個視窗切到別的資料夾就隱藏，重啟後也直接回來，讓便利貼跟著「地方」而不是跟著某個視窗。
32b. 身為使用者，我想在 Safari 或 Chrome 貼的便利貼綁在那個網頁上：任何分頁或視窗打開同一個網址就出現，換到別的網頁就隱藏，重啟後也直接回來，讓網頁筆記不會掛在不相干的分頁上。
33. 身為使用者，我想在 Codex 或瀏覽器上貼便利貼時，它明確綁在視窗範圍，讓我知道這些 App 不支援對話／網址層級。
34. 身為使用者，我想建立浮動便利貼（不綁定、始終顯示、所有桌面可見），讓我放一些隨時要看的東西。
35. 身為使用者，我想把浮動便利貼重新綁到目前內容，或把綁定的便利貼改成浮動，讓兩種用法互通。

### 顯示與隱藏

36. 身為使用者，我想只有當目標是前景 App 的焦點內容時便利貼才出現，讓它不會蓋在別的 App 上。
37. 身為使用者，我想切走時便利貼立刻隱藏，回來時在原位置、原收合狀態出現，讓我的版面被記住。
38. 身為使用者，我想快速連續切換對話或 App 時，舊內容的便利貼絕不會短暫出現在新內容上，讓我不被誤導。
39. 身為使用者，我想拖動或縮放目標視窗時，便利貼維持與視窗的相對位置（可以貼在視窗外緣、但不會跑出螢幕），讓它始終貼在我放的地方。
40. 身為使用者，我想目標視窗最小化時便利貼隱藏，還原時重新出現。
41. 身為使用者，我想目標視窗進入全螢幕時便利貼仍出現在該全螢幕空間上，讓全螢幕工作也能用。
42. 身為使用者，我想把目標視窗移到另一個螢幕時便利貼跟過去，讓多螢幕也正確。
43. 身為使用者，我想從選單列「暫時隱藏全部」（含浮動便利貼），讓我在分享螢幕時保護隱私。

### 重啟與找回

44. 身為使用者，我想 Hintlet 或 Claude 重啟後，Claude 對話的便利貼自動回到正確的對話，讓我不用重新整理。
45. 身為使用者，我想一般 App 重啟後（視窗身分無法延續；只有 Hintlet 重啟、視窗還開著時便利貼直接回來），原本綁在視窗（讀不到資料夾／文件路徑）的便利貼不會被猜測後自動貼上，而是進「待找回」。
46. 身為使用者，我想在該 App 標題完全相同的視窗回到前景時看到「可能是這裡？」的小標記，按一下就確認重新綁定，讓找回只要一步；標題不同的視窗不打擾我。
47. 身為使用者，我想所有無法匹配的便利貼都保留在「待找回」，讓筆記永遠不會無聲消失（沒有寫任何內容的空白便利貼除外，見 7a）。

### 集中列表

48. 身為使用者，我想按 ⌘⌥L 開集中列表，讓我一次看到所有便利貼。
49. 身為使用者，我想全文搜尋所有便利貼，讓我找到某段筆記。
50. 身為使用者，我想列表依 App 與工作內容分組並顯示綁定目標與範圍，讓我知道每張貼在哪。
51. 身為使用者，我想列表有「待找回」區，可對其中便利貼重新綁定、改為浮動或刪除。
52. 身為使用者，我想列表有「垃圾桶」區可復原。
53. 身為使用者，我想（若驗證可行）從列表按「前往」直接切到該 Claude 對話，讓我從筆記跳回工作。

### 權限與設定

54. 身為使用者，我想第一次需要輔助使用權限時看到說明用途，再前往系統設定授權，讓我知道為什麼需要它。
55. 身為使用者，我想第一次綁定 Claude 對話前看到說明（需讓 Claude 開啟完整輔助使用樹、會多用一些資源），並可拒絕；拒絕時 Claude 只用視窗範圍。
56. 身為使用者，我想在設定裡更改全域快捷鍵，讓它不和我其他工具衝突。
57. 身為使用者，我想匯出所有便利貼為備份檔並能匯入，讓我能備份或搬家。
58. 身為使用者，我想 App 只出現在選單列、不佔 Dock，讓它不打擾。
59. 身為使用者，我想不需要授予「輸入監控」或「螢幕錄製」權限，讓 App 的權限越少越好。

### AI 便利貼（第二階段）

60. 身為使用者，我想在對話範圍的便利貼剛貼下時看到半透明選項「✨ 讓 AI 記錄脈絡？」，讓我一鍵把它變成 AI 便利貼。
61. 身為使用者，我想一開始打字該選項就消失，讓手寫便利貼不受干擾。
62. 身為使用者，我想每個對話最多一張 AI 便利貼，已存在時不再出現選項。
63. 身為使用者，我想從別的工作切回來時一眼抓到重點：AI 便利貼寫出粗體的「目標」（整段對話的大目標，小步驟與插曲不改它）、「重點」（最新進展的結論本身，不是「回答了…」這類動作），以及只在需要我時出現的「下一步」（等你／卡住／進行中），與更新時間。
64. 身為使用者，我想 AI 便利貼是唯讀的，AI 永遠不會改動我的手寫便利貼。
65. 身為使用者，我想切走一個對話時其 AI 便利貼自動更新，讓我回來時看到最新狀態。
66. 身為使用者，我想手動按「更新」，讓我隨時取得最新摘要；Claude 每次回完，AI 便利貼就自動更新。
67. 身為使用者，我想 Code 與 Cowork 的 AI 便利貼讀取完整對話紀錄，讓摘要完整。
68. 身為使用者，我想 Chat 的 AI 便利貼在只讀到部分內容時標示「僅根據已載入的 N 則訊息」，且不推測未看到的內容。
69. 身為使用者，我想預設使用 Apple 裝置端模型，讓內容不離開本機。
70. 身為使用者，我想可在設定中主動改用 Claude API（自行填入 key），並清楚知道這代表內容會上傳。
71. 身為使用者，我想所有 AI 便利貼使用同一個顏色（預設淡藍），可在設定中改，讓我一眼分辨 AI 與手寫。
72. 身為使用者，我想從動態島或右鍵選單把對話上的便利貼（寫過字也可以）「轉成 AI 便利貼」，或把 AI 便利貼「轉成一般便利貼」（內容就是 AI 便利貼當下顯示的摘要），讓我事後也能改。

## Implementation Decisions

### 專案與平台

- macOS 14 以上；AI 裝置端模型需要較新系統，功能在不支援時隱藏。
- Xcode App 專案（使用同步資料夾），App 程式只負責 AppKit／系統整合；核心邏輯放在本地 Swift package，可用 `swift test` 獨立測試。命令列以 `xcodebuild` 建置。
- 以使用者 Apple ID 的 Apple Development 身分簽章（首次建置允許自動申請憑證），簽章穩定使輔助使用授權不因重建失效。
- 不啟用 App Sandbox（輔助使用與跨 App 讀取受限）。選單列 App（無 Dock 圖示）。
- 全域快捷鍵使用不需輸入監控權限的系統熱鍵註冊；預設 ⌘⌥N 新增、⌘⌥L 列表，可在設定變更。
- Bundle ID：`com.jyp.stickycontext`。名稱：Hintlet。

### 模組

- **ContextProvider**：每個受支援的 App 一個 adapter，把系統觀測轉成「工作內容觀測」：App bundle ID、視窗身分、視窗在螢幕上的 frame 與狀態（最小化／全螢幕／所在螢幕）、可辨識到的最細工作內容與其範圍、信心（確定／降級／不可綁定）、顯示用標題。
  - 一般 adapter：視窗範圍；視窗有文件路徑（AXDocument）時為資料夾／文件範圍。
  - Finder adapter：Finder 不提供 AXDocument，以 Apple Event 詢問前景 Finder 視窗的資料夾（需要「控制 Finder」權限；拒絕時退回視窗範圍）。
  - Claude adapter：由網頁區域的 AXURL 取得對話 ID（見下方「Claude 識別」）。原始 AX 讀取與「快照 → 識別」的純邏輯分離，後者是測試切面 B。
- **BindingResolver**：給定目前工作內容觀測與所有便利貼，決定哪些便利貼符合；處理降級、待找回、「可能是這裡？」候選與重新綁定。不做任何以標題為唯一依據的自動匹配。
- **NoteStore**：保存便利貼（含綁定、錨點位置、尺寸、收合、顏色、刪除時間）與 AI 摘要；JSON 單一檔案、帶格式版本、原子寫入、保留最近 5 份備份；匯出／匯入使用同一格式並做版本遷移。
- **OverlayController**：每張便利貼一個不搶焦點的浮動面板，可在所有空間與全螢幕空間顯示；負責顯示／隱藏、跟隨視窗、多螢幕座標轉換、收合標籤、編輯時的焦點處理。
- **SummaryService**（第二階段）：可替換的後端協定（裝置端模型；會上傳的 Claude 帳號、Codex 帳號、Claude API、OpenAI API），輸入為經允許的對話內容與涵蓋程度，輸出三行摘要、涵蓋標記與更新時間。與手寫便利貼與視窗追蹤完全解耦。
- **核心引擎**（測試切面 A）：組合 BindingResolver、NoteStore 與版面計算；輸入為「工作內容觀測」串流、使用者操作、時鐘；輸出為「應顯示的便利貼集合」（每張的螢幕 frame、收合狀態、範圍標籤）。AppKit 層只是把這個輸出畫出來、把事件餵進去。

### 資料模型（概念）

- 便利貼：id、種類（手寫／AI）、綁定（可為空 = 浮動）、文字內容、顏色（手寫）、錨點（綁定視窗的角落 + 位移，浮動則為螢幕座標與所在螢幕）、尺寸、收合、建立／更新時間、刪除時間（非空 = 在垃圾桶）。
- 綁定：範圍（對話／資料夾或文件／視窗）、App bundle ID、識別資訊：
  - 對話：Claude 分頁種類（Chat／Cowork／Code）+ 對話 ID。
  - 資料夾或文件：路徑（持久，跨執行自動匹配；路徑是精確識別，不是猜測）。
  - 視窗：本次執行期的視窗身分，加上持久的指紋：系統視窗編號＋所屬 App 的這次執行（pid 與啟動時間），只要視窗與 App 都還開著，Hintlet 重啟後直接對回（精確，不是猜測）；標題、frame 僅用於「可能是這裡？」候選（同 App 且標題完全相同），不用於自動匹配。
  - 綁定狀態：已匹配／待找回（含原因：App 重啟、對話不存在等）。
- AI 摘要：三行內容、涵蓋程度（完整／部分 N 則／不足）、使用的後端、更新時間；每個對話最多一個 AI 便利貼。

### Claude 識別

- 依 AXURL 路徑判斷：`/chat/<uuid>` → Chat 對話；`/cowork/<id>` → Cowork session；`/epitaxy/local_<uuid>` → Code session；`/new`、`/task/new` 與沒有 session 的 Code 首頁 → 新對話草稿（不可綁定）；網址帶 `#settings` 時（設定是蓋在目前頁面上的視窗）→ 暫時隱藏該對話的便利貼，不可新貼；其他頁（專案…）→ 降級為視窗範圍。路徑格式不符預期一律降級，不猜測。
- 目前顯示的網頁區域：由焦點元素向上找最近的網頁區域，退而求其次取主視窗中尺寸非零的網頁區域；無法確定 → 降級。
- 顯示用標題：Cowork／Code 讀本機 session 檔的標題；Chat 讀網頁區域標題。
- 刪除偵測：Cowork／Code 的本機 session 檔消失 → 便利貼移到垃圾桶。Chat 不偵測。
- 第一次需要時才對 Claude 開啟完整輔助使用樹，並先徵求同意（拒絕則只提供視窗範圍）。

### 切換偵測與防閃爍

- 事件優先：App 啟用通知、視窗焦點／移動／縮放／最小化等 AX 通知。AXURL 變化無通知，僅在 Claude 位於前景時，以低頻率（約 0.5–1 秒）讀取已快取網頁區域的網址；Code 另以本機 session 檔的 `lastFocusedAt` 變化作輔助訊號。
- 任何前景／焦點變化先**同步隱藏**所有不再確定符合的便利貼，再解析新內容；只有在新內容確定後才顯示。寧可晚一點出現，不可錯誤出現。
- 前景 App 變成 Hintlet 自己（例如在編輯便利貼）時，沿用前一個工作內容，不觸發隱藏。

### 第三方

- 不 fork、不複製 tack 程式碼（ADR-0002）；UX 參考 tack 與 TackNote。

## Testing Decisions

- 好的測試只驗證外部行為：給定一串觀測與操作，「應該顯示哪些便利貼、在哪、什麼狀態」，以及重啟後讀回的結果；不測內部資料結構或私有方法。
- **切面 A（核心引擎）**：以假的工作內容觀測、假時鐘與暫存資料夾中的 NoteStore 驅動。涵蓋：多張便利貼的匹配與範圍標籤、對話與視窗範圍並存、降級、新對話頁拒絕、跟隨視窗移動／縮放／換螢幕的座標計算、最小化與全螢幕狀態、快速切換不出現舊便利貼、前景為自己時不隱藏、刪除／復原／垃圾桶到期、session 刪除進垃圾桶、App 重啟後視窗便利貼進待找回與「可能是這裡？」確認、範圍變更與重新綁定、浮動便利貼、以新引擎讀回同一資料夾驗證持久化、格式版本遷移與匯出匯入往返。
- **切面 B（Claude adapter 的「AX 快照 → 識別」）**：以技術原型從真實 Claude 錄下的快照為測試素材（Chat、Cowork、Code、新對話、設定頁、多個網頁區域、非預期網址）。
- 第二階段新增 **SummaryService 切面**：以假模型驗證三行格式、涵蓋程度標記、不覆寫手寫便利貼、切走時觸發更新。
- 真實 AX 呼叫、浮動面板、全螢幕與多螢幕不寫自動化測試，以技術原型與驗收清單手動（必要時以 computer-use）驗證，結果記錄在驗證報告。
- 專案目前沒有既有測試可參考；採 Swift Testing 框架。

## Out of Scope

- 以分頁為單位的綁定：Safari 分頁無穩定 ID。網頁改以網址綁定（故事 32b、ticket 18），不需要分頁 ID。
- Codex 對話綁定：路由不在 AXURL 中，只能靠標題，不符可靠識別要求（ADR-0001）。視窗範圍可用。
- 終端機中的 Claude Code CLI 對話綁定：排在第四階段。
- 「專案」範圍（資料夾／文件範圍已納入，見故事 32a）。
- 富文字、圖片、提醒、語音、堆疊等 TackNote 功能。
- iCloud 同步、多使用者、多台電腦。
- 持續錄製螢幕、OCR。

## Further Notes

### 階段

1. **技術原型**：驗證 Claude 三種分頁的 AXURL 識別與切換延遲、錄下切面 B 的測試快照、Chat 能否讀到完整內容、`claude://` 能否開到指定對話、浮動面板能否顯示在全螢幕空間、編輯便利貼是否引起顯示循環。結果決定「前往」與 Chat 完整讀取是否納入。
2. **手寫便利貼 MVP**。
3. **AI 便利貼**。
4. **Claude Code CLI 對話綁定**。

每階段完成在本機 git commit。

### 驗收清單

1. 在 Claude 兩個 Chat 對話之間切換，各自顯示正確的便利貼；Cowork、Code 各測一次。
2. 新對話頁拒絕貼並提供「改貼在這個視窗」；點側欄舊對話不誤判。
3. 快速連續切換對話或 App 時，舊便利貼不閃到新內容上。
4. 移動、縮放、最小化 Claude 視窗，進出全螢幕，在兩個螢幕之間移動。
5. 重開 Claude 與 Hintlet 後，便利貼都在且正確對應回對話。
6. 便利貼取得焦點時，不因前景變成自己而隱藏造成循環。
7. 一般視窗綁定（例如 Finder）與重啟後的「可能是這裡？」提示。
8. 刪除後復原；Code session 被刪時便利貼進垃圾桶。
